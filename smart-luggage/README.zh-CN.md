# smart-luggage — 智能行李箱

基于 **STM32F103C8 + FreeRTOS V11.1.0** 的智能行李箱系统，毕业设计作品。

[English](README.md) | **简体中文**

## 功能

| 功能 | 硬件 | 接口 |
|---|---|---|
| GPS 定位 | ATGM336H（GPS + 北斗双模） | USART1 @ 9600 |
| 指纹开锁 | ZW101 | USART2 @ 9600 + PA1 触摸（EXTI） |
| 云端通信 | ESP8266 + OneNET MQTT | USART3 @ 115200 |
| 物理锁 | 继电器 | PB12（GPIO） |
| 防丢告警 | 蜂鸣器 | TIM1_CH1N（PWM） |
| 状态显示 | OLED | I2C |

## 架构

六个 FreeRTOS 任务：

| 任务 | 优先级 | 职责 | 阻塞在什么上 |
|---|---|---|---|
| `log` | 1 | 日志串行化（全工程唯一的 printf 出口） | 队列（永久等待） |
| `hb` | 2 | OLED 刷新 + 每秒状态日志 | `vTaskDelay(1000)` |
| `lock` | 3 | 指纹帧解析 / 开锁 | 队列（100 ms）+ 信号量 |
| `alarm` | 3 | 蜂鸣器仲裁 | 事件组（1000 ms 超时兜底） |
| `gps` | 4 | NMEA 解析 | 队列（3000 ms） |
| `comm` | 5 | AT 状态机 / 位置上报 / AT 探活 | 任务通知 |

优先级按**截止时间**排（判断依据是"晚多少毫秒会出问题"），**不按"重要性"** —— 云端心跳超时的代价最直接，所以 `comm` 最高。

五种 IPC 机制都是真用上的：队列（3 个）、互斥量（2 个）、二值信号量、事件组、任务通知。所有中断服务函数都用 `...FromISR` 版本 API，而且**没有任何任务在轮询** —— 六个任务全部阻塞在某个"等"上面。

## 为什么上 RTOS

裸机版有两个**可证明的**缺陷，都在这个版本里修掉了：

1. **按指纹时死等** —— 裸机版是 `while (PA1 == SET) {}`，手指放在传感器上的整段时间里，主循环完全停摆。而 GPS 接收缓冲只有 200 字节（9600 bps 下每字节约 1.04 ms），**约 0.2 秒就写满** —— 也就是说，**用户正在本地开锁的那几秒，远程开锁恰好是失灵的**。这不是理论风险，是结构上的必然。

2. **联网时盲等 13 秒** —— 连续 6 次 `delay_ms(3000)`，不看应答、失败不重试。ESP8266 没插、或者路由器没开，这 13 秒照样白等，等完还是连不上。

## 编译

Keil MDK 5 + ARM Compiler 6，严格 C99。

打开 `xinglix_RTOS.uvprojx` 直接编译。结果：**0 错误 0 警告**，Flash 47.0 KB / RAM 17.2 KB。

**编译前**需要把 `code/secrets.h.example` 复制为 `code/secrets.h`，填入自己的 WiFi 和 OneNET 凭据 —— 真实凭据文件有意不放进本仓库。
